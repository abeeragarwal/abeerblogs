# The Hardest Step is the First Step

*"You don't have to be great to start, but you have to start to be great." — Zig Ziglar*

For the longest time, I talked myself out of starting a blog. I kept telling myself I needed to be "ready" first. Maybe after I mastered Data Structures and Algorithms. Or after grinding through 500 problems on LeetCode. Or after building some mind-blowing portfolio.

The truth is that my perfectionist brain was just making excuses. I realized there is no magical moment where you suddenly feel ready. There is only right now.

## Why I Finally Started

I was learning something new every single day. I would spend hours debugging a nasty piece of code, wrestling with a tricky DSA problem, or setting up a personal project. It felt like a waste to let all those insights disappear into thin air.

I wanted a place to document what I learn and track my growth over time. I also love teaching. In a world that often feels pretty self-centered, sharing what you know is a small way to help the person coming up behind you.

## Taking the Harder Route

When I finally committed to building this site, I refused to use WordPress, Medium, or a drag-and-drop editor. I wanted to build the platform using the actual skills I was trying to learn.

So I picked a dynamic stack that fits my flow. I write everything in Obsidian, build the site using Hugo, and host it for free on GitHub Pages.

Was it extra work? Absolutely. But I wanted the entire publishing process to feel like an extension of being a developer. I wanted a system that grows with me and belongs entirely to me. No ads, no paywalls, and no platform rules.

## How the Engine Works

Obsidian is where the magic starts. It is a local note-taking app that uses plain Markdown files. It lets me link ideas together and organize my thoughts offline without any lag or distraction. I drafted this exact post inside my vault.

Next comes Hugo, which is a lightning-fast static site generator built in Go. Hugo takes those plain Markdown files from Obsidian and transforms them into clean HTML. I use the PaperMod theme to handle the design, and a single terminal command builds the whole site in seconds.

Finally, GitHub Pages hosts the generated files. I set up a GitHub Action so the whole deployment is automated.

My current workflow looks like this:

1. Write the post in Obsidian
    
2. Commit the changes
    
3. Push to GitHub
    
4. The site goes live automatically

## Just Start

Building this blog was about taking full ownership of my learning process. It is not perfect, but it is mine.

If you are waiting for the ideal moment to start your own blog or project, stop waiting. Start messy, learn as you go, and figure out the rest later.
